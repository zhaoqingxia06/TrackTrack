# 采集、存储和可靠性

- 优先复用现有架构，提供统一 track API 和字段校验；操作、结果、页面事件在语义正确的位置触发。发送失败不阻塞产品功能；设计有界队列、批量发送、重试、退出时尽力发送及失败可观测性，浏览器关闭不能保证送达。
- 同一事件重试保持 event_id，服务端按事件 ID 幂等；检查必填、类型、字段白名单、大小、版本及时间，拒绝或隔离异常记录。客户端发生时间、服务端接收时间和顺序号分别保留，跨设备时钟不可靠时注明排序限制。
- 明确定义事件原始表、轨迹/会话及持续过程之间的关联；聚合可重算，不替代原始数据。测试/演示环境数据分开，禁止自动造数伪装用户数据。限制查询访问、保护传输和存储、设定保留期限与删除机制；上线前根据产品用户和地区核对告知、同意及适用要求。
- 默认不采集输入内容、密码、身份信息、Cookie、完整 URL 查询串或屏幕内容；确需敏感字段或录屏时先明确目的和边界并依据适用要求处理。监测工具及回放本身应排除采集。
- 文档写明接口、配置、部署、迁移、备份、容量及失败诊断方式；适配现有技术栈，不承诺无损采集或无限扩展。若依赖第三方，应注明费用、许可和数据流向。
